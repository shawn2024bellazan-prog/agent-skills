# Workflows

## Purpose

Turn a useful dynamic AGENTS workflow into a reusable script while preserving project/global precedence and the host's workflow-generation behavior.

## When to Use

- Saving a multi-agent run or dynamic workflow for reuse.
- Reviewing where an existing workflow script lives and how it is invoked.
- Choosing between a dynamic workflow, a single-file command, and a skill directory.

## When Not to Use

- Creating a focused static slash command; use `author-commands`.
- Creating an on-demand workflow that needs bundled resources; use `author-skills`.
- Assuming arbitrary hand-written scripts will be recognized as supported workflows.

## Inputs

| Input | Required | Description |
|-------|----------|-------------|
| Workflow to preserve | Yes | The successful dynamic workflow or multi-agent run. |
| Scope | If known | Project-shared or global/personal; discover the existing workflow context if unspecified. |

## Workflow

1. Confirm that the run is a dynamic workflow worth reusing, rather than a single prompt or a skill with supporting files.
2. Use `/workflows` to save the run as the host supports; avoid hand-writing a script when the workflow is expected to be generated by the agent.
3. Choose project `.claude/workflows/` for a shared workflow or global `~/.claude/workflows/` for a personal one.
4. Confirm the saved JavaScript file's name and that it is exposed as the intended `/<name>` command.
5. Check for a same-named project workflow: project workflows take precedence over global workflows.

## Validation

- [ ] The workflow was saved through the supported workflow flow.
- [ ] The script is in the intended project or global directory and has the expected name.
- [ ] The workflow is available through the intended slash command.
- [ ] Any same-named project/global conflict is understood.

## Common Pitfalls

| Pitfall | Solution |
|---------|----------|
| Hand-writing a script when the host expects saved workflow output | Save the run through `/workflows`. |
| Using a workflow for a simple prompt | Prefer a single-file command. |
| Using a workflow for a reusable procedure with bundled resources | Prefer a skill. |
| Forgetting project-over-global precedence | Check the project workflow before relying on the global one. |
